同一个模型、同一个问题：把它接到你的收藏上（RAG），回答会落到你真正收藏过的帖子、能给出处、能被核对； 不给它收藏（无 RAG），它只能给泛泛的通用建议。右边并排放在一起，差别一眼可见。

🧩 预处理：收藏 → 可检索 ✅ 真实（③④⑤） i 三步都是纯计算，可以人工复算（PRD 4.2 ③④⑤）。
• ③ 分块：按 段落 > 句末标点 > 逗号 > 硬切 的优先级切块；chunkSize 由正文长度中位数推导、overlap 取 20%，相邻块共享一小段以免切断语义。保真约束：去掉重叠后拼接必须逐字等于原文（AC-4）。
• ④ 分词：CJK 单字 + 相邻双字（bigram）+ 拉丁词（长度 ≥2）。查询侧会把含功能字的 bigram（如「吃的」）丢掉，语料侧不丢。
• ⑤ 建索引：N = chunk 数、|D| = chunk 字符数、df = 含该词的 chunk 数、avgdl = Σ|D|/N。

这三步决定「检索能命中什么」，但观众真正关心的答案在前面两块，所以这里默认收起。

⑦检索与打分（真 BM25） 🔶 混合来源 i 打分本身是真算的 BM25（PRD 4.2 ⑦ / FR-7）：
IDF(t) = ln(1 + (N - df(t) + 0.5)/(df(t) + 0.5))（平滑 IDF，恒为正；df=0 的词跳过）
score = Σ IDF(t) × tf(t,D)×(k1+1) / (tf(t,D) + k1×(1 - b + b×|D|/avgdl))，k1=1.2、b=0.75。
文档 D = chunk 正文、单字段，标题不参与打分。

三遍策略：① 原词精确遍 → ② 改写遍（原词 0 命中时，用原词 + 改写词 + 主题词）→ ③ 放宽遍（还没命中才加单字，排除虚字表，结果标「宽松命中」）。 第 ② 遍就是「混合来源」的由来；每条结果都会显示命中词及其来源与贡献分。

与 xhs-rag 不同：插件是自制 TF 变体（无 IDF、无长度归一化、标题 ×3），本页结论不可外推（R1 / D12=P1）。
⑧Prompt 组装（两份并排） ✅ 真实 i 纯字符串拼接（PRD 4.2 ⑧ / FR-9），所以标 ✅ 真实。
这里给出两份 prompt，正是上面两栏回答的输入：
• 有 RAG：系统提示 → 本次意图与检索说明 → 【用户收藏库引用】（或整库总览）→【其他参考内容（非收藏库）】→ 用户问题。无命中时写入明确指令，不留空。
• 无 RAG 基线：只说「用户没有提供任何私人资料，用通用知识回答、不需要出处」，再给同一个问题。

两份 prompt 都可以复制；每份都标注了哈希，用来核对上面两栏回答是不是真的对应这份输入。
