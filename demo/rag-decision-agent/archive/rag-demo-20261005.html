① 链接识别

对粘贴文本做正则提取 + 主机分类 + 笔记 id 解析 + 去重，规则与 xhs-rag/urls.js 一致，全部在本地字符串层面完成（交接说明 §3.1）。 短链不展开：展开短链要发网络请求，本页不做（PRD 4.1 Out of Scope），这里只把它单独识别出来。

示例文案里刻意放了：带 ?xsec_token 的长链、/discovery/item/ 长链、重复出现的同一条链接、以全角逗号结尾的 xhslink.cn 短链、用户主页（非笔记页）、/explore/ 空 id、非小红书域名、#话题 标签。

② 抓取与解析

这里展示的就是内嵌假数据本身：每条素材的标题、作者、正文字数、是否可用；降级笔记给出完整中文原因句。

🔶 模拟：此处结果是预置的，未发起任何网络请求。真实抓取要跨域、要过风控，静态单文件页面做不到（PRD 4.2 ②）。

③ 分块 Chunking

纯字符串处理：按 段落换行 > 句末标点（。！？；） > 逗号 > 硬切 的优先级找切点，切片之间只保留 overlap。 降级笔记照常参与分块（PRD 4.5，与 xhs-rag 行为一致）：这条内容不完整，但同样会被检索到。

④ 分词

规则与 xhs-rag/search.js:24-49 一致：先转小写；拉丁词与数字按 [a-z0-9_]+ 切、只留长度 ≥ 2； CJK 段逐字 push 单字，并在与下一字同属 CJK 时 push 相邻双字（bigram）。emoji、#、标点天然被忽略，不会报错（B8）。

⑤ 建索引

口径（交接说明 §3.4）：N = chunk 总数（不是笔记数）、|D| = chunk 字符数（不是 token 数）、 df(t) = 含 t 的 chunk 数、avgdl = Σ|D| / N、词典 = 所有 chunk 的 token 去重集合。

⑥ 检索词构建

真实系统里这一步是生成任务、要过 LLM（知识库文档 337–361 行）。本页用「规则 + 预置映射」近似，所以标为模拟。 不参与打分（D11）。

⚠️ 本页展示的三分类不参与打分；真实系统里它会影响检索结果。
⑦ 的打分只使用用户 query 的原词分词结果，⑥ 与 ⑦ 之间没有数据流。 这样规定是因为：一旦让模拟环节的产出进入打分，⑦ 就不能再标「✅ 真实」。

⑦ 检索与打分（真 BM25）

公式（交接说明 §3.5）：IDF(t) = ln(1 + (N - df + 0.5)/(df + 0.5))， score(D,Q) = Σ IDF(t) × tf(t,D)×(k1+1) / (tf(t,D) + k1×(1 - b + b×|D|/avgdl))，k1=1.2、b=0.75。 文档 D = chunk 文本，单字段，标题不参与打分。两遍策略：精确遍（多字 token）完全无命中时，才放宽到单字（排除虚字表）并标注「宽松命中」。
