小红书收藏 → 生活决策助手 i 这个工具在做什么
它把你收藏的小红书帖子当作私有知识库：先做预处理（分块 → 分词 → 建索引）， 再用你的问题去检索，最后给出带出处的决策建议。所以 query 可以是生活化的 「国庆节去哪儿玩」，也可以是「整理我的收藏夹」。

三条硬声明
1. 12 条帖子是人工构造的，不是真实小红书内容，也不是抓取结果；
2. 本页不发任何网络请求，断网双击即可用；
3. 本页用真 BM25，xhs-rag 插件用自制 TF 变体（无 IDF、无长度归一化、标题 ×3）， 本页排序结论不能用来推断插件的线上表现。

四种标记
✅ 真实 当场算的，可人工复算； ✅ 真实 LLM 产出 真实模型生成后内嵌（离线可看，不是当场调用，附 prompt 哈希校验）； 🔶 模拟 预置的 / 规则近似 LLM； 🔶 混合来源 BM25 计算是真的，但参与打分的词有一部分来自模拟的改写环节。

③分块 Chunking i 纯字符串处理（PRD 4.2 ③ / FR-4），所以标 ✅ 真实。
切点优先级：段落换行 > 句末标点（。！？；）> 逗号 > 硬切到 chunkSize。

参数不写死，由测量推导：先量出正文长度的中位数， chunkSize = round(中位数 × 0.5)、overlap = round(chunkSize × 0.2)。 约束：chunkSize 夹到 [40, 2000]，overlap 夹到 [0, chunkSize-1]；非法输入夹取并提示（B14）。

为什么要有 overlap：切点落在一句话中间时，相邻两块各持半句，谁都不完整； 让相邻块共享一小段，可以救回这种被切断的语义。代价是同一段文字会被算两次。

保真约束（AC-4）：把每个 chunk 去掉与上一块重叠的部分再顺序拼接，必须逐字等于原文。 页面上的「保真校验」是当场算的。

内容不完整的帖子照常参与分块。
④分词 i 零依赖分词，规则与 xhs-rag/search.js:24-49 一致（PRD 4.2 ④），所以标 ✅ 真实。
1. 整段转小写；2. 拉丁词与数字按 [a-z0-9_]+ 切出、只留长度 ≥2； 3. CJK 连续段逐字 push 单字，并与下一个字同属 CJK 时 push 相邻双字（bigram）。

为什么用 bigram：中文没有词边界，「云南」「粉底」这类双字比两个孤立单字更能表达检索意图。
代价是 bigram 会跨词边界：「好吃的」会切出「吃的」。

查询侧的一条规范化规则：如果某个 bigram 的任意一个字是功能字（的/着/么/什/怎/呢/吧…）， 查询侧就把这个 bigram 丢掉 —— 否则「上海有什么好吃的」会被「吃的」带到丽江那篇去。 这张功能字表刻意很窄：像「上海」含「上」、「中餐」含「中」，这些内容词不受影响。 语料侧不做这个丢弃（否则 df 口径会变），所以它只影响查询词。被丢掉的词在 ④ 里会列出来。

返回值保留重复（重复即出现次数），查询侧先按 token 去重。emoji、#、标点、空格天然被忽略（B8）。

⑥意图识别与检索词构建 i 真实系统里这一步是生成任务、要过 LLM（知识库文档 337–361 行）。本页用「规则 + 预置映射」近似，所以标 🔶 模拟。

检索词分三类来源（页面上逐词标注）：
• 原词：用户 query 自己切出来的词（✅ 真实来源）；
• 改写词：预置改写表把生活口语换成能命中的检索词，例如 国庆 → 假期/出行/旅游（🔶 模拟）；
• 主题词：意图映射到的收藏主题的种子词，例如 云南 → 云南/大理/丽江（🔶 模拟）。

为什么要让改写词参与检索（重要变更）
早期 PRD 规定三分类不参与打分，好处是 ⑦ 可以标「✅ 真实」； 但那样一来「国庆节去哪儿玩」在收藏里必然 0 命中，agent 就答不出生活化的问题。 本版按新需求让改写词参与检索，并按 PRD 4.2 ⑥ 预留的口径把 ⑦ 改标为 🔶 混合来源 —— 不是把模拟说成真实，而是把来源摊开给你看：
⑦ 会逐词标出每个命中词来自 原词 / 改写 / 主题，以及它贡献了多少分。
⑦检索与打分（真 BM25） i 打分本身是真算的 BM25（PRD 4.2 ⑦ / FR-7）：
IDF(t) = ln(1 + (N - df(t) + 0.5)/(df(t) + 0.5))（平滑 IDF，恒为正；df=0 的词跳过）
score(D,Q) = Σ IDF(t) × tf(t,D)×(k1+1) / (tf(t,D) + k1×(1 - b + b×|D|/avgdl))， k1=1.2、b=0.75，|D| = chunk 字符数，N = chunk 总数。
文档 D = chunk 正文、单字段，标题不参与打分（不做 BM25F）。

为什么标「混合来源」：参与打分的词里，有的来自用户原词（真实），有的来自 ⑥ 的改写 / 主题词（模拟）。 每一行结果都会显示命中词及其来源，你可以自己判断这次结论有多可靠。

三遍策略
1. 原词精确遍：只用 query 原词里的多字 token；
2. 改写遍：原词 0 命中时，改用 原词 + 改写词 + 主题词（仍是多字 token）。这是混合来源的来源；
3. 放宽遍：仍然 0 命中时，才加 CJK 单字（排除虚字表），结果标注「宽松命中、相关度较低」。
两遍都能命中时以更靠前的那遍为准 —— 宁可少给几条，也不让单字噪声淹没真正的匹配。

排序与确定性（AC-6）：主序 score 降序，次序 chunkId 字典序升序（tie-break 必须有）。
与 xhs-rag 不同：插件是自制 TF 变体（无 IDF、无长度归一化、标题 ×3），本页结论不可外推（R1 / D12=P1）。

1. 系统提示：角色 = 帮用户从 TA 自己的收藏里做生活决策；必须标出处；收藏里没有的可以说，但必须说明那不是收藏里的；不许编造。

这样拼接的好处：模型能看到「哪些是可引用的私有知识、哪些只是通用常识」，回答里的出处也能对得上。
