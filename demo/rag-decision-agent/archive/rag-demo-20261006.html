③ 分块 Chunking i 纯字符串处理（PRD 4.2 ③ / FR-4），所以标 ✅ 真实。
切点优先级：段落换行 > 句末标点（。！？；）> 逗号 > 硬切到 chunkSize。

参数不写死，由测量推导：先量出 12 条正文长度的中位数，chunkSize = round(中位数 × 0.5)、overlap = round(chunkSize × 0.2)。 约束：chunkSize 夹到 [40, 2000]，overlap 夹到 [0, chunkSize-1]；非法输入会被夹取并提示，不静默接受（B14）。

游标必须始终前进（nextStart > start），否则参数极端时页面会卡死。

保真约束（AC-4）：把每个 chunk 去掉与上一块重叠的部分再顺序拼接，必须逐字等于原文。页面上的「保真校验」是当场算的，不是写死的结论。

降级（内容不完整）的笔记照常参与分块，并会说明「这条内容不完整，但同样会被检索到」。

④ 分词 i 零依赖分词，规则与 xhs-rag/search.js:24-49 一致（PRD 4.2 ④ / 交接说明 §3.2），所以标 ✅ 真实。
1. 先整段转小写；
2. 拉丁词与数字按 [a-z0-9_]+ 切出，只保留长度 ≥ 2 的；
3. CJK 连续段：逐字 push 单字，并在与下一个字同属 CJK 时 push 这个相邻双字（bigram）。

为什么用 bigram：中文没有词边界，「云南」「粉底」这类双字比两个孤立单字更能表达检索意图，是零依赖下最接近分词的近似。

返回值保留重复（重复即出现次数），但查询侧必须先按 token 去重。emoji、#、标点、空格天然被忽略，也不会因此报错（B8）。

⑤ 建索引 i 全量语料在页面内，可精确计算（PRD 4.2 ⑤ / FR-5），所以标 ✅ 真实。
口径（交接说明 §3.4）：
• N = chunk 总数（不是笔记数）
• |D| = 该 chunk 的字符数（不是 token 数）
• tf(t,D) = token t 在 chunk D 中的出现次数
• df(t) = 含 t 的 chunk 数
• avgdl = (Σ|D|) / N；词典 = 所有 chunk 的 token 去重集合

别把 Σ|D| 和原文总字数搞混：chunk 之间有 overlap，同一段字符会被相邻两块各算一次，所以 Σ|D| 比正文总字数大。这是口径本身如此，不是重复计数 bug。

⑥ 检索词构建 i 真实系统里这一步是生成任务、要过 LLM（知识库文档 337–361 行），本页用「规则 + 预置映射」近似，所以标 🔶 模拟。

三分类的含义：核心词（必须匹配）/ 扩展词（建议匹配）/ 排除词（必须过滤）。
本页规则：核心词 = query 里长度 ≥ 2 的 token；扩展词 = 预置同义词表命中的词（没有映射时显式说明，不留白、也不假装是模型输出）；排除词 = 命中通用排除表的词。

为什么必须写明「不参与打分」（D11 / 评审 Blocker #1）
⑥ 与 ⑦ 之间没有数据流：打分只用用户 query 的原词分词结果。一旦让模拟环节的产出进入打分，⑦ 就不能再标「✅ 真实」，整页的真实性结论都会塌。

本页展示的三分类不参与打分；⑦ 只用 query 的原词分词打分。（真实系统里它会影响检索结果。）

⑦ 打分与排序（真 BM25） i 真算 BM25（PRD 4.2 ⑦ / FR-7），所以标 ✅ 真实。
IDF(t) = ln(1 + (N - df(t) + 0.5) / (df(t) + 0.5)) —— 平滑 IDF，恒为正；df=0 的查询词直接跳过。
score(D,Q) = Σ_{t∈Q} IDF(t) × tf(t,D)×(k1+1) / (tf(t,D) + k1×(1 - b + b×|D|/avgdl))
k1 = 1.2、b = 0.75、|D| = chunk 字符数、N = chunk 总数。

文档 D = chunk 文本，单字段；标题不参与打分（不做 BM25F），标题命中只在结果层作辅助展示。

两遍策略（D13，照搬 xhs-rag）
• 精确遍：只用多字 token（中文 bigram、拉丁词）；
• 放宽遍：只在精确遍完全无命中、且查询里确实还有单字可放宽时才执行（加入 CJK 单字、排除虚字表），结果标注「宽松命中、相关度较低」；
• 两遍都命中时以精确遍为准 —— 宁可少给几条，也不让单字噪声淹没真正的匹配。

排序与确定性（AC-6）：主序 score 降序，次序 chunkId 字典序升序。tie-break 必须有，否则同一 query 两次可能给出不同顺序。

与 xhs-rag 的算法不同（R1 / D12=P1）：插件是自制 TF 变体（无 IDF、无长度归一化、标题 ×3，另乘覆盖率因子），本页排序结论不可外推。

⑧ Prompt 组装 i 纯字符串拼接（PRD 4.2 ⑧ / FR-9），所以标 ✅ 真实。
输出顺序固定：
1. 系统提示（说明角色，以及「只用参考内容回答」的要求）；
2. 参考内容块：按检索结果顺序逐条列出，每条含 出处（标题 / 作者 / URL）+ chunk 文本；
3. 用户问题。

无命中分支必须写（对应知识库文档第 512 行）：prompt 里要出现明确指令，告知模型「本次没有检索到相关内容，请如实说明没找到，不要编造」，不允许留空。

⑨ 回答生成与出处 i 🔶 模拟生成（PRD 4.2 ⑨ / FR-10，D14 决定保留）。
回答由检索命中的片段按固定模板拼接，不是任何模型产出，也没有调用任何模型。

三条硬约束：
• 区域顶部必须标「🔶 模拟生成」；
• 禁止显示任何置信度 / 相似度 / 概率数字 —— 没有真算，显示了就是编造；
• 每条引用附 标题 + 作者 + URL + 命中片段，且可点击回到所属笔记卡片；无命中时只回答「没有找到相关内容」，不编造。
