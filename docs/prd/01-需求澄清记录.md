### xhs-rag 的真实数据契约（这是假数据字段的依据，不是我设计的）

- **存储文件**：`<homeDir>/storages/xhs-rag/notes.json`，结构 `{ version: 1, savedAt, notes: [...] }`（`store.js:51-61`）
- **单条笔记**（`index.js:181-190`）：

  | 字段 | 类型 | 说明 |
  |---|---|---|
  | `noteId` | string | 笔记 id |
  | `url` | string | 规范化 URL，形如 `https://www.xiaohongshu.com/explore/<noteId>`（`urls.js:194`） |
  | `title` | string? | 已去掉「- 小红书」后缀（`parse.js:101-105`） |
  | `text` | string | 正文，来自 `meta description` |
  | `author` | string? | 昵称 |
  | `degraded` | string[] | **降级原因的完整中文句子数组** |
  | `usable` | boolean | 是否达到可用阈值（`MIN_USABLE_TEXT = 40`） |
  | `importedAt` | string | ISO 时间 |

- **检索返回**（`index.js:317-345`）：`{ query, queryTokens, matchMode: 'precise'\|'loose', scanned, totalInStore, hits[], notes[] }`

### 一条重要的实测约束（来自 xhs-rag，非我推断）

小红书笔记页是 JS 渲染的，纯 HTTP 只能拿到 `<title>` 与 `<meta name="description">`；**图片型笔记的正文抓不到**，只能标记 `degraded`。这条约束被本 demo 用作教学内容（12 条假数据里有 2 条刻意降级）。

## 五、第 2 轮新发现的分歧 → 第 3 轮已全部关闭

### 分歧 1：demo 的"真 BM25"与 xhs-rag 的实际算法不是一回事 → 定 **P1**（D12）

- `search.js:143-184` 的真实实现**不是 BM25**：`score = Σ [3×(1+ln tf_title) + 1×(1+ln tf_body)] × (1 + 覆盖率)` —— **没有 IDF，没有文档长度归一化**。
- 后果：同一个 query，demo 与插件可能给出**不同的排序**。
- 处置：**P1** —— 只实现 BM25，页面上写明"本页算法与 xhs-rag 插件不同，结论不可外推"。P2（加算法切换开关、并排真算）已记录在 PRD 4.2 中备查，日后可作为 v2 提案重新评估。

### 分歧 2：是否照搬插件的"精确遍 + 放宽遍"两遍策略 → 定 **照搬**（D13）

- 照搬后 `樟脑丸防虫` 的"宽松命中"演示成立，FR-8、场景 3、AC-10 全部有效。
- 若改用纯标准 BM25，上述三项都要改写。已否决。

### 另外两项在第 3 轮一并关闭

- **三分类是否参与打分** → 不参与（D11）。这是自查出的最严重问题：若参与，PRD 4.2 表 ⑦ 的「✅ 真实」结论不成立。
- **FR-10 回答生成是否保留** → 保留，且必须标注模拟（D14）。
