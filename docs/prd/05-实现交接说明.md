## 3. 精确算法规格

### 3.1 分块（③，✅ 真实）

1. **参数测量推导**（不得写死）：先量 12 条正文长度的**中位数**，`chunkSize = round(中位数 × 0.5)`、`overlap = round(chunkSize × 0.2)`。
   **v0.4 实测**：中位数 168 → `chunkSize=84`、`overlap=17`；N=34；10/12 条 ≥2 块。
2. 切分优先级：段落换行 > 句末标点（`。！？；`）> 逗号 > 硬切到 `chunkSize`；标点归前一块。
3. 参数夹取：`chunkSize → [40, 2000]`、`overlap → [0, chunkSize-1]`；非法输入夹取后**在界面上提示**（B14）。
4. **游标必须始终前进**（`nextStart > start`），否则极端参数下会死循环。
5. **保真约束（AC-3）**：每块去掉与上一块重叠的 `dupPrefix` 后顺序拼接，必须**逐字等于原文**。
   v0.4 在 4 组参数下全量核过（含 `40/39`、`200/199`）。
6. 内容不完整的帖子**照常分块**。

### 3.2 分词（④，✅ 真实）

1. 整段转小写；
2. 拉丁词与数字按 `[a-z0-9_]+` 切，只保留长度 ≥ 2；
3. CJK 连续段：逐字 push 单字，并在与下一字同属 CJK 时 push 相邻双字（bigram）；
4. 返回值**保留重复**（重复即出现次数），查询侧先按 token 去重；
5. emoji / `#` / 标点 / 空格天然被忽略（B8）。

**查询侧追加规则（v0.4 新增）**：若某个 bigram 的**任意一个字属于「功能字表」**，查询侧丢弃它。
功能字表刻意很窄：`的着过们么呢吧吗啊呀哦嗯之而或与及也就都还太更最把被给让使什怎咱`。
理由：「上海有什么好吃的」会切出「吃的」并把丽江那篇带进来；而 `上`/`中` 这类字若一并列入，会误杀
「上海」「中餐」。**语料侧不做这个丢弃**（否则 df 口径会变）。

**测试向量（与 `search.js:24-49` 一致，v0.4 仍逐条通过）**

| 输入 | 期望输出 |
|---|---|
| `厨房收纳` | `厨 厨房 房 房收 收 收纳 纳` |

| `的` | `的` |
| `樟脑丸防虫` | `樟 樟脑 脑 脑丸 丸 丸防 防 防虫 虫` |

### 3.3 建索引（⑤，✅ 真实）

| 量 | 口径 |
|---|---|
| `N` | **chunk 总数**（不是帖子数） |
| `\|D\|` | 该 chunk 的**字符数**（不是 token 数） |
| `tf(t,D)` | token t 在 chunk D 中的出现次数 |
| `df(t)` | **含 t 的 chunk 数** |
| `avgdl` | `(Σ\|D\|) / N` = 2160 / 34 = **63.529** |
| 词典 | 所有 chunk 的 token 去重集合（v0.4 实测 **1688**） |

界面必须能给「本次检索会用到的每个词」的 **来源 / df / IDF / 倒排表**；df=0 的词标注「打分时跳过」。

### 3.4 意图与检索词（⑥，🔶 模拟）

**意图表**（按优先级：收藏夹整理 → 出行 → 美食 → 美妆；都不命中为通用检索）：

| 意图 | 触发词 | 关联主题 | 路径 |
|---|---|---|---|
| 收藏夹整理 | 收藏/收藏夹/整理/归档 | 不限定（可带聚焦主题） | 全库聚合 |
| 出行决策 | 旅游/旅行/出行/去哪/玩/国庆/假期/攻略/云南/大理/丽江/香格里拉 | 云南旅游 | 关键词检索 |
| 本地美食 | 吃/餐厅/美食/探店/日料/本帮菜/咖啡/早午餐/夜宵/上海 | 上海餐厅 | 关键词检索 |
| 美妆选购 | 粉底/底妆/化妆/美妆/油皮/敏感肌/护肤/防晒/色号/定妆/卸妆 | 敏感肌油皮粉底液 | 关键词检索 |

**检索词三类来源**（逐词标注）：原词（✅ 真实来源）/ 改写词（🔶 预置改写表）/ 主题词（🔶 主题种子词）。

改写表示例：`国庆→假期/出行/旅游`、`去哪→推荐/攻略`、`好吃→餐厅/美食`、`美妆→粉底/护肤`。
主题种子词示例：`yunnan→云南/大理/丽江/香格里拉/旅游/攻略`。

### 3.5 BM25（⑦）

```
IDF(t)     = ln(1 + (N - df(t) + 0.5) / (df(t) + 0.5))
score(D,Q) = Σ_{t∈Q} IDF(t) × ( tf(t,D)×(k1+1) ) / ( tf(t,D) + k1×(1 - b + b×|D|/avgdl) )
k1 = 1.2        b = 0.75        |D| = chunk 字符数
```

- **文档 D = chunk 文本，单字段；标题不参与打分**（不做 BM25F）。
- `df(t)=0` 的查询词直接跳过；平滑 IDF 恒为正。
- 排序：主序 score 降序，次序 `chunkId` 字典序升序（tie-break 必须有，否则 AC-6 会挂）。
- 显示：总分 3 位小数，分项贡献 4 位小数。

### 3.6 三遍策略（⑦ 的「混合来源」由来）

1. **原词精确遍**：只用 query 原词的多字 token → 命中则 `tokenSource=query`；
2. **改写遍**：原词 0 命中时，用 原词 + 改写词 + 主题词（仍是多字 token）→ 命中则 `tokenSource=mixed`；
3. **放宽遍**：仍 0 命中时，加入 CJK 单字（排除虚字表）→ 标「宽松命中、相关度较低」。

更靠前的一遍有命中就不进入下一遍。**⑦ 必须标 🔶 混合来源**，并在每条结果里逐词标出 来源与贡献分 ——
这是 PRD 4.2 ⑥ 当初预留的口径（「若改为参与打分，则 ⑦ 必须改标为混合来源」）。

### 3.7 收藏夹整理（query 提及收藏时）

- 不做关键词命中，直接对全库做**真实聚合**（按主题分组、条数、可用/不完整），把帖子本身作为引用；
- query 里带主题词时（如「整理我的美妆收藏」）额外补一遍该主题检索作为重点引用；
- 聚合 ✅ 真实计算；意图判断 🔶 模拟。

### 3.8 两份 Prompt（⑧，✅ 真实拼接）

**有 RAG**（顺序固定）：

1. 系统提示：只依据【用户收藏库引用】回答、标出处编号；可用【其他参考内容】但必须声明那不是收藏里的；
   收藏里没有就说没找到；**不输出任何置信度 / 相似度 / 概率数字**；
2. 【本次意图与检索说明】：意图、命中方式（走的哪一遍）、打分来源（原词 / 混合）、被丢弃的 bigram；
3. 【用户收藏库引用】（或收藏夹整理的【用户收藏库总览】）；无命中时写入明确指令，**不留空**；
4. 【其他参考内容（非收藏库）】：按意图给的通用经验（🔶 预置内容），每条带 `[G1]` 这类编号；
5. 【用户问题】。

**无 RAG 基线**：只说「用户没有提供任何私人资料；用通用知识回答、不需要标注出处、不输出置信度数字」+ 同一个问题。
两份 prompt 都展示全文、可复制，并各自显示 `hashText()` 结果。

### 3.9 决策建议（⑨，✅ 真实 LLM 产出 + 模板兜底）

- **默认路径**：用内嵌的真实模型输出（`answers-v4.json`）。页面用**当前构建出的 prompt** 重算 FNV-1a 哈希，
  `promptSha` 一致才展示；不一致（例如用户改了分块参数）则**退回模板拼接**并明确标注 + 告诉用户怎么恢复。
- 两栏：**有 RAG**（引用可点击回到帖子卡片）与 **无 RAG 基线**（明确写「这栏没有任何出处」）。
- 附**人工整理的对照小结**（页面标注「不是模型输出」）。
- 硬约束：不显示任何置信度 / 相似度数字；非收藏库段落单独标注；空态时说「收藏里没有找到」，不编造。

### 3.10 事件（8 类）

`demo_load` / `index_build` / `query_submit` / `query_result` / `prompt_preview` / `answer_render` /
`sim_badge_view` / `export_events`。字段见 PRD 第 6 节。刷新清零，不持久化。

> 相比 v1 的 10 类：`link_parse` 随环节 ① 删除、`quiz_submit` 随「理解自测」删除。

## 9. 本文能替代什么、不能替代什么

- **能替代**：把 500+ 行 PRD 读三遍。公式、常量、测试向量、验证命令都在这里。
- **不能替代**：PRD 本身。第 5 节（边界与异常）、第 6 节（埋点）、第 9 节（验收标准）以 PRD 为准。
- **发现实现与规格冲突时**：先改 PRD 再改代码，不要在实现里悄悄绕过 —— 这会让验收标准与实际行为脱钩，
  正是本 demo 想避免的失败模式。
