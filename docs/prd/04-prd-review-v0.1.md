# PRD 评审意见：RAG 教学演示页 v0.1

> 评审对象：[02-rag-web-demo-PRD.md](02-rag-web-demo-PRD.md) v0.1
> 评审日期：2026-10-05 ｜ 使用的技能：`prd-review`
> 结论边界：本文只依据 PRD 正文、[需求澄清记录](01-需求澄清记录.md)与 [假数据样例](03-mock-xhs-notes.json) 评审；不涉及实现质量。

## 总体结论

**需先补齐 2 项 Blocker 再评审。** 其余 9 项重要问题可在评审会同场答复，不需要预先改写。

第 1 项 Blocker 尤其要紧：它**推翻的是这份文档自己的真实性结论**——第 4.2 节把「检索打分」标为「✅ 真实计算」，但检索用的 token 来自哪个环节，文档里从未定义。如果用了上游那个被标为「🔶 模拟」的检索词构建结果，那么「✅ 真实」就是错的，而这恰好是 D8（方案 A）和 G2/G4 的立足点。

## 做得好的地方

- **4.2 真实性对照表**：把 9 个环节逐个标「真算 / 模拟」并给出依据（可复用的源文件、文档行号），这是「不虚构数据」这条规则最直接的落地，也是这份文档最有价值的一节。
- **第 6 节主动声明埋点边界**：写明「单文件静态页没有服务端，埋点不能做漏斗分析、不能跨人聚合」，并显式记下 G4 无埋点可支撑的缺口，没有假装能测。
- **R1 主动暴露自相矛盾**：把「demo 用 BM25，而 xhs-rag 用自制 TF 变体」这个不一致写进风险，并给出 P1/P2 两个选项与代价，而不是掩盖过去。
- **假数据字段严格对齐真实实现**：`noteId/url/title/text/author/degraded/usable/importedAt` 直接取自 `index.js:181-190`，`degraded` 是可直接展示的中文句子（来自 `parse.js` 的判定分支），未来接真实数据源不需要改结构。
- **AC-10 用 5 条预置 query 覆盖 5 种结果态**（正常命中 / 短词命中 / 纯虚字 / 宽松命中 / 零命中），把「检索质量」这种模糊话题变成了可勾选的检查。
